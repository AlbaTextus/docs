# 生产部署与升级

## 入口与域名

正式部署应使用同源 HTTPS 入口，正确设置 `ISSUER_URL`、`AUTH_UI_URL`、`WEBAUTHN_RP_ID`、`WEBAUTHN_RP_ORIGINS` 和 `COOKIE_SECURE=true`。反向代理保留 `/api/`、`/oauth/`、`/.well-known/` 的转发；健康检查直接请求 Go 的 `/healthz`。启用 CSP 时，为 Turnstile 放行 `https://challenges.cloudflare.com` 的脚本与 iframe。

浏览器会访问下面几个入口，它们必须与账户页面共享同一 Cookie 主机范围：

| 入口 | 后端 | 说明 |
| --- | --- | --- |
| 账户前端 | Next.js `3288` | 将 `/api/v1/*`、`/oauth/*`、`/.well-known/*` 转发到 OAuth `8001`，将 `/api/v4/*` 的创作者操作转发到 `8004` |
| `NEXT_PUBLIC_ATHUB_API_URL` | ATHub `8005` | 小说库直连 `/api/v5/*`，不经过 Next.js |
| `NEXT_PUBLIC_CREATPLAT_API_URL` | 创作者平台 `8004` | 历史与贡献者查询直连 |
| `IMAGE_PUBLIC_URL` | 图床 `8002` | 图片地址 `/file/<ID>` 与上传接口 |

`NEXT_PUBLIC_*` 地址在前端构建时写入，变化后需要重建前端。反向代理不经回环地址连接后端时，把它的网段加入 `TRUSTED_PROXY_CIDRS`，否则登录限速等按来源地址生效的规则会把所有请求算作同一个来源。不要混用 `localhost` 和 `127.0.0.1`，Cookie 与 Passkey 的来源校验可能因此不一致。

## 健康检查

四个模块各自提供 `/healthz`，直接请求 Go 监听的端口：

| 端口 | 模块 | 结果 |
| --- | --- | --- |
| `8001` | OAuth | 正常返回 200；维护模式返回 433；账户库或维护状态读取失败返回 503 |
| `8002` | 图床 | 正常返回 200 |
| `8004` | 创作者平台 | 创作者库和账户库都可用时返回 200，否则返回 503 |
| `8005` | ATHub | 内容库不可用返回 503 |

任一端口绑定失败时，程序会释放已绑定的端口并整体退出，不会只启动一部分模块。

## 密钥与备份

数据库迁移应作为独立发布步骤执行。加密密钥须与数据库一起备份、多实例保持一致；已有客户端只有哈希而没有加密副本时，需重置后才能在后台查看明文。不要在每次部署时重新生成加密密钥，也不要在生产使用 seed 的默认凭据。

- 备份范围包括四套数据库、`CLIENT_SECRET_ENCRYPTION_KEY`、`.env` 以及图床的文件目录 `IMAGE_LOCAL_ROOT`。
- 图床的对象文件与图床库不在同一个事务里，两者需要一起备份、一起恢复，见[图床失败恢复](/image/recovery)。

## 升级清单

1. 备份数据库、加密密钥和图片目录。
2. 停止旧版本后端。创作者库和图床的数据导入都要求先停写。
3. 执行有变化的数据库迁移，见[数据库与迁移](/deploy/database)。
4. 更新后端程序和前端构建，保留已有的 `.env`。
5. 启动后端与前端，检查四个 `/healthz`，再放开入口流量。

创作者库已经接收新的审核或修订之后，不能只把连接切回旧库来回退，见[创作者平台数据库](/creatplat/database)的回退限制。需要对外暂停服务时可以使用维护模式，见[站点开关与维护](/oauth/site)。

## 多实例

- 加密密钥在所有实例上保持一致。
- ATHub 的读缓存在进程内，多实例之间不会即时失效，由缓存有效期兜底，见 [ATHub 模块与数据库](/athub/module)。
- Redis 会话缓存可选；关闭时每次请求直接核验账户库。
