# 生产部署与升级

## 入口与域名

正式部署应使用同源 HTTPS 入口，正确设置 `ISSUER_URL`、`AUTH_UI_URL`、`WEBAUTHN_RP_ID`、`WEBAUTHN_RP_ORIGINS` 和 `COOKIE_SECURE=true`。反向代理保留 `/api/`、`/oauth/`、`/.well-known/` 的转发；健康检查请求各模块的 `/api/v{n}/healthz`，前端不转发根路径 `/healthz`。启用 CSP 时，为 Turnstile 放行 `https://challenges.cloudflare.com` 的脚本与 iframe。

浏览器会访问下面几个入口，它们必须与账户页面共享同一 Cookie 主机范围：

| 入口 | 后端 | 说明 |
| --- | --- | --- |
| 账户前端 | Next.js `3288` | 将 `/api/v1/*`、`/api/v2/*`、`/api/v3/*`、`/oauth/*`、`/.well-known/*` 和 `/api/v4/*` 转发到聚合入口 |
| `NEXT_PUBLIC_ATHUB_API_URL` | 聚合入口 `8010` | 浏览器直连 `/api/v5/*`，不经过 Next.js |
| `NEXT_PUBLIC_CREATPLAT_API_URL` | 聚合入口 `8010` | 浏览器直连 `/api/v4/*` 查询历史与贡献者 |
| `IMAGE_PUBLIC_URL` | 聚合入口 `8010` | 图片地址 `/file/<ID>` 与上传接口 |

`NEXT_PUBLIC_*` 地址在前端构建时写入，变化后需要重建前端。反向代理不经回环地址连接后端时，把它的网段加入 `TRUSTED_PROXY_CIDRS`，否则登录限速等按来源地址生效的规则会把所有请求算作同一个来源。不要混用 `localhost` 和 `127.0.0.1`，Cookie 与 Passkey 的来源校验可能因此不一致。

## 聚合端口

后端只使用一个 HTTP 监听地址 `GATEWAY_HTTP_ADDR`，默认 `:8010`。模块不再各自监听，也不再启动旧文件端口。反向代理只需一个 API 上游，转发时保留原路径和查询参数：

| 路径前缀 | 模块 |
| --- | --- |
| `/api/v1`、`/oauth`、`/.well-known` | OAuth |
| `/api/v2`、`/file` | 图床 |
| `/api/v3` | 邮件 |
| `/api/v4` | 创作者平台 |
| `/api/v5` | ATHub |

未匹配的路径（含根路径 `/healthz`）返回 404 `not_found`。各模块保留自己的来源校验、鉴权、限速和请求期限。

`NEXT_PUBLIC_ATHUB_API_URL`、`NEXT_PUBLIC_CREATPLAT_API_URL` 和 `IMAGE_PUBLIC_URL` 可以使用同一个公开 API 域名。该域名反代到 `8010`，仍须与账户页面共享 Cookie 主机范围。

封面文件上传及插图和布局读写走同一入口的 `/api/v4`，见[创作者平台接口](/creatplat/api)。若反向代理按路径放行，需允许 `/api/v4`，不能只允许 `/api/v5`；邮箱验证码走 `/api/v3`，同样需要放行。后端不再提供旧 `v5` 插图接口。

## 健康检查

五个模块的健康检查都走 `8010`，按版本前缀区分：

| 路径 | 模块 | 结果 |
| --- | --- | --- |
| `/api/v1/healthz` | OAuth | 正常返回 200；维护模式返回 433；账户库或维护状态读取失败返回 503 |
| `/api/v2/healthz` | 图床 | 正常返回 200；图床库或文件目录不可用返回 503 |
| `/api/v3/healthz` | 邮件 | 账户库可用时返回 200，否则返回 503；未配置 SMTP 不影响结果 |
| `/api/v4/healthz` | 创作者平台 | 创作者库和账户库都可用时返回 200，否则返回 503 |
| `/api/v5/healthz` | ATHub | 内容库不可用返回 503；不需要 Key，也不计入调用记录 |

例如 `http://127.0.0.1:8010/api/v4/healthz` 检查创作者平台。监控按模块配置上表的五条路径；内置 `healthcheck` 命令使用 `GATEWAY_HTTP_ADDR` 下的 `/api/v1/healthz`。

聚合端口绑定失败时，后端整体退出。

## 密钥与备份

数据库迁移应作为独立发布步骤执行。加密密钥须与数据库一起备份、多实例保持一致；已有客户端只有哈希而没有加密副本时，需重置后才能在后台查看明文。不要在每次部署时重新生成加密密钥，也不要在生产使用 seed 的默认凭据。

- 备份范围包括四套数据库、`CLIENT_SECRET_ENCRYPTION_KEY`、`.env` 以及图床的文件目录 `IMAGE_LOCAL_ROOT`。
- 图床的对象文件与图床库不在同一个事务里，两者需要一起备份、一起恢复，见[图床失败恢复](/image/recovery)。

## 升级清单

1. 备份数据库、加密密钥和图片目录。
2. 停止旧版本后端。
3. 执行有变化的数据库迁移，见[数据库与迁移](/deploy/database)。其中「需要留意的迁移」列出的删表、删列迁移不可恢复，执行之后旧版本后端也无法再启动。
4. 更新后端程序，保留 `.env` 中的数据库和密钥配置，将 `GATEWAY_HTTP_ADDR` 改为 `:8010`，删除不再读取的模块及旧文件监听配置。
5. 将反向代理上游、前端代理和客户端指向聚合入口。修改了前端转发目标或 `NEXT_PUBLIC_*` 地址时重新构建前端。如果仍需访问旧图床 URL，让原公开入口把 `/file/` 转发到 `8010`，无需启动旧文件监听。
6. 启动后端与前端，在聚合入口检查各模块的 `/api/v{n}/healthz`，再放开入口流量。

创作者库已经接收新的审核或修订之后，不能只把连接切回旧库来回退，见[创作者平台数据库](/creatplat/database)的回退限制。需要对外暂停服务时可以使用维护模式，见[站点开关与维护](/oauth/site)。

## 多实例

- 加密密钥在所有实例上保持一致。
- ATHub 的读缓存在进程内，多实例之间不会即时失效，由缓存有效期兜底，见 [ATHub 模块与数据库](/athub/module)。
- 会话不做缓存：每个实例对每次请求都直接核验账户库，退出登录和撤销在所有实例上立即生效。
- 图床的存储渠道配置与 IP 黑名单在每个进程内缓存 5 秒；在一个实例上修改后，其他实例最多延迟 5 秒生效。
